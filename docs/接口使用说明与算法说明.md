## 一、项目是什么

本项目是「软件工程2」课程设计：把上学期的**稀疏 SfM** 算法，扩展并封装成一个完整的**三维重建系统**。

完整链路（从图片到模型）：

```
图片 → 特征提取(SIFT) → 特征匹配 → 相机参数估计 → 稀疏点云 → 密集重建 → 模型优化(网格化)
```

技术栈：Python 3.14 + OpenCV + PyTorch(CUDA) + open3d。

## 四、对外接口（重点）

### 4.1 统一入口 `reconstruct_full()` —— B/C 直接用它

```python
from sfm_project import reconstruct_full

result = reconstruct_full(
    "images2",        # 图片目录，或图片文件路径列表（环拍需按序传入）
    save=True,        # 是否把产物写到 output/
    do_dense=True,    # 是否做稠密重建
    do_mesh=True,     # 是否做网格化
    visualize=False,  # 服务端必须 False，否则弹 matplotlib 窗口
    dense_kwargs=None,  # 覆盖稠密参数，见 4.5
    mesh_kwargs=None,   # 覆盖网格参数，见 4.5
)
```

**返回 `FullResult`**（字段见 4.3）。最常用的是：

```python
result.mesh_glb       # 前端 Three.js 直接加载的 GLB 路径
result.dense_ply      # 稠密点云 PLY 路径
result.mesh_ply       # 网格 PLY 路径
result.num_points     # 最终点云数量
result.to_dict()      # JSON 可序列化字典（统计 + 产物路径）
```

> **`save` 参数说明**：`True` 时点云/网格都写进 `output/`；`False` 时只算不写（用于测试试跑）。默认 `True`。

> **`do_dense` / `do_mesh`**：只想拿稀疏点云时把两者都关掉；`do_mesh=True, do_dense=False` 时会在稀疏点云上网格化（质量差，一般不用）。

### 4.2 稀疏入口 `reconstruct()` —— 只要稀疏点云用

```python
from sfm_project import reconstruct

result = reconstruct("images2", save=False, visualize=False)
# 返回 ReconstructionResult，默认不写盘、不弹窗
```

### 4.3 结果对象字段

**`ReconstructionResult`（稀疏结果）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `points` | (N,3) ndarray | 稀疏三维点坐标 |
| `colors` | (N,3) ndarray | 颜色 RGB 0-255 |
| `reprojection_error` | float | 平均重投影误差（像素） |
| `num_points` | int | 点数 |
| `num_images` | int | 参与重建（已跳过坏帧后）的图像数 |
| `timings` | dict | 各阶段耗时（秒） |
| `rotations` | list | 每帧相机旋转（世界→相机） |
| `motions` | list | 每帧相机平移（世界→相机） |
| `registered_indices` | list | 每帧位姿对应的原始图像索引（跳帧后与图像全集不再一致） |
| `to_dict()` | dict | JSON 可序列化（只含标量统计） |

**`DenseResult`（稠密结果，`reconstruct_full` 内部）**

| 字段 | 说明 |
|---|---|
| `points` / `colors` | 稠密点坐标 (M,3) / 颜色 (M,3) |
| `depth_map` / `cost_map` | 主视图逐像素深度 / NCC 成本（出图用） |
| `near` / `far` | 深度扫描范围 |
| `ref_indices` | 实际参与扫描的参考视图索引 |
| `num_points` / `num_views` / `to_dict()` | 统计属性 |

**`FullResult`（全链路结果，`reconstruct_full` 返回）**

| 字段 | 说明 |
|---|---|
| `sparse` | `ReconstructionResult` |
| `dense` | `DenseResult`（`do_dense=False` 时为 None） |
| `mesh` | open3d `TriangleMesh` 对象（`do_mesh=False` 时为 None） |
| `dense_ply` / `mesh_ply` / `mesh_obj` / `mesh_glb` | 产物路径（未生成则为 None） |
| `images_used` | 参与重建的图像数 |
| `num_points`（属性） | 最终点云数量（有稠密用稠密） |
| `to_dict()` | JSON 可序列化统计 + 路径 |

### 4.4 配置 `Config`

`config.py` 里的 `Config` 类，`reconstruct_full` / `reconstruct` 不传 `config` 时会自动新建：

| 配置 | 默认 | 说明 |
|---|---|---|
| `AUTO_CALIBRATE` | `True` | 流水线开始时自动确定内参 K（EXIF→默认） |
| `FEATURE` | SIFT 参数 | nfeatures=0(不限) 等 |
| `MATCHING.ratio` | `0.5` | Lowe's ratio test 阈值 |
| `RECONSTRUCTION.min_matches` | `8` | 注册一帧的最少匹配点数 |
| `RECONSTRUCTION.reproj_threshold` | `0.5` | 重投影误差阈值 |
| `BA.use_cuda` | `True` | BA 用 CUDA 并行过滤 |
| `DATA_PATH` | `../images2` | 默认数据集路径 |
| `OUTPUT_PATH` | `output/` | 产物目录 |

**稠密重建常用参数（`dense_kwargs`）**：

| 参数 | 默认 | 说明 |
|---|---|---|
| `num_ref_views` | 6 | 参考视图数量（多视图融合） |
| `num_depths` | 256 | 每视图深度平面数（越大越精细越慢） |

## 五、算法说明

### 5.1 稀疏 SfM

```
SIFT 特征提取 → BFMatcher + ratio test 顺序匹配 → 本质矩阵 recoverPose 初始化
→ PnP(RANSAC) 增量注册新帧 → 三角化新点 → BA 优化 → 稀疏点云
```

1. **特征**：`cv2.SIFT_create`，每张图提几百个特征点 + 描述子。
2. **匹配**：相邻帧 BFMatcher 匹配，Lowe's ratio test（默认 0.5）滤误匹配。
3. **初始化**：前两帧用 `findEssentialMat` + `recoverPose` 恢复相对位姿，三角化出初始点。
4. **增量**：后续每帧用 PnP（RANSAC）求位姿，再与上一帧三角化出新 3D 点并融合。
5. **BA**：重投影误差优化（CPU 版 `scipy.least_squares` 优化点坐标；CUDA 版实为并行算误差后按阈值过滤）。

### 5.2 自动标定内参 K

优先级：**EXIF 焦距（mm→像素）→ 默认 f = 1.0 × 图像宽**（方形像素、主点在图像中心）。

> **为什么不用自标定**：曾试基础矩阵 F 的两种自标定（σ1=σ2 奇异值约束、cheirality+重投影搜索），在环拍数据上都会落到搜索边界 f=0.5W 的**伪极小值**，结果在 0.78W~1.2W 乱跳。故弃用，改走稳健可预测的「EXIF→默认」路线。

### 5.3 跳过坏帧

增量重建用**惰性匹配**：当前帧匹配「最近一次成功注册的帧」（而非相邻编号的帧）。坏帧被跳过后不会让后续帧错位。

同时用 `registered_indices` 记录每帧位姿对应的原始图像索引，后续颜色/BA/稠密重建都用对齐后的子集。

### 5.4 稠密重建（plane-sweep stereo）

原理：选一张参考图，在其前方扫一排深度平面；深度为 d 的平面在两个相机间诱导一个**单应变换** H(d)=K(d·R_rel+t_rel·nᵀ)K⁻¹，把其他视角 warp 到参考视角；对每个像素在所有视角比颜色一致性，一致性最好的深度就是该像素深度。

关键步骤：
1. **NCC 一致性**（归一化互相关）：patch 内先零均值+归一化再算相关系数，对亮度/对比度差异不敏感。
2. **亚像素深度细化**：在 cost 曲线上做抛物线拟合（逆深度域插值）。
3. **多视图融合**：对 5~6 个参考视图各扫一遍，点云融合成 360° 覆盖（单视图只能出 2.5D 曲面，喂 Poisson 会被强制闭合成一坨，所以必须多视图）。
4. **后处理**：左右一致性校验（LRC）、斜射剔除、统计离群点剔除（SOR）。

### 5.5 网格化

```
Poisson 重建(depth=8) → bbox 裁剪 → 密度裁剪 → 二次误差简化 → Laplacian 平滑 → 顶点着色 → 导出
```

- **密度裁剪**：用原始点云的 KDTree 检查网格顶点附近有无点支撑，砍掉 Poisson 在空区域（天空/鼓包）凭空生成的曲面。
- **着色**：当前是「点云颜色就近映射到网格顶点」的**顶点着色**，不是正式纹理贴图（见第七节）。

### 5.6 坐标约定（务必记牢）

- `rotations[i]` / `motions[i]` 是**世界→相机**变换。
- 投影：`x = K (R X + t)`。
- 相机中心：`C = -Rᵀ t`。
- 第 0 帧是世界原点（R=I, t=0）。
- 稠密重建和网格化都沿用这套约定，别改反。

## 七、已知限制与后续项

1. **纹理映射未做**：网格目前是顶点着色，模型偏暗、可能把天空/背景颜色贴进去。正式 UV 纹理贴图是后续项。
2. **未跑全分辨率**：稠密重建默认 `max_dim=720` 降采样，未在 2832×2128 全分辨率验证。
3. **多段重建未支持**：若数据集中间有「场景断层」（相邻帧几乎无重叠），断层后的帧会被整段跳过（当前只支持一条连续序列）。
4. **CUDA BA 名不副实**：`bundle_adjustment_cuda.py` 不是真正的 BA，只是并行算重投影误差后按阈值过滤点；真正的优化在 CPU 的 `bundle_adjustment.py`。
